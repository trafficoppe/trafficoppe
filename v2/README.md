# CCTV v2 — แยกหน่วยงาน MLC / LA / PMH (branch `cctv-multi-unit`)

> **สถานะ: รุ่นทดสอบ ยังไม่เปิดใช้** — ไฟล์ทั้งหมดอยู่ในโฟลเดอร์ `v2/` เท่านั้น
> `index.html`, `index_en.html`, `admin.html` ที่รากของ repo **ไม่ถูกแก้ไข** และ URL เดิมยังทำงานตามเดิม
> ยังไม่ได้ Deploy Apps Script ใหม่ และยังไม่ได้แตะ Sheet จริง

## ทางเข้าแยกหน่วยงาน

| หน่วยงาน | URL (หลังนำขึ้นใช้งาน) |
|---|---|
| อาคารศูนย์การเรียนรู้มหิดล (MLC) | `…/v2/index.html?unit=mlc` |
| อาคารสิริวิทยา (LA) | `…/v2/index.html?unit=la` |
| มหิดลสิทธาคาร (PMH) | `…/v2/index.html?unit=pmh` |

- เปิดโดยไม่มี `?unit=` หรือระบุผิด → แสดงหน้าเลือกหน่วยงาน และ**ซ่อนแบบฟอร์ม** จึงบันทึกผิดหน่วยงานไม่ได้
- เลขอ้างอิงมีรหัสหน่วยงาน เช่น `CCTV-MLC-20261114-AB12` และหลังบ้านจะปฏิเสธถ้ารหัสในเลขอ้างอิงไม่ตรงกับหน่วยงาน
- `v2/qr.html` สร้าง QR Code ของทั้ง 3 หน่วยงานพร้อมพิมพ์ (แก้ที่อยู่เว็บฐานได้บนหน้า)
- ค่าเริ่มต้นเป็น **โหมดทดสอบ**: `CCTV_V2_CONFIG.scriptUrl` ว่าง → กดส่งแล้วไม่ส่งข้อมูลออกไปที่ใด

## โครงสร้าง Sheet ใหม่ (สร้างด้วย `setup()` ใน Sheet ทดสอบ)

| แท็บ | เนื้อหา |
|---|---|
| `REQ_MLC`, `REQ_LA`, `REQ_PMH` | คำขอของแต่ละหน่วยงาน |
| `REQ_CENTRAL` | ข้อมูลเดิมของส่วนกลาง (คำขอ 11 รายการในระบบปัจจุบัน) |
| `ALL_REQUESTS` | มุมมองรวมทุกหน่วยงานด้วยสูตร `QUERY` (ห้ามพิมพ์ทับ) |
| `STATS` | จำนวนคำขอ / รอดำเนินการ / ปิดเคส ต่อหน่วยงาน |
| `UNIT_OFFICERS` | `unit, role, name, email, notify, note` — ตอนนี้เป็น placeholder (`…@example.invalid`, notify = FALSE) |
| `NOTIFY_QUEUE` | คิวแจ้งเตือน — บันทึกสถานะ `QUEUED_NOT_SENT` เท่านั้น ยังไม่ส่งอีเมล/ข้อความ |

คอลัมน์: 44 คอลัมน์เดิมของ `CCTV_Requests` **ตำแหน่งเดิมทุกคอลัมน์** แล้วต่อท้ายด้วย `unit, unitName, formVersion, legacyRow`
(ต่อท้ายเพื่อไม่ให้สูตร/รายงานที่อ้างตำแหน่งคอลัมน์เดิม เช่น PDF รายเดือน คลาดเคลื่อน)

## แผนย้ายข้อมูลเดิม (ยังไม่ได้รัน)

ผลสำรวจ ณ 14 พ.ย. 2569: `CCTV_Requests` มี 11 คำขอ (17 เม.ย.–11 พ.ย. 2569) สถานะ “ปิดเคส” ทั้งหมด
สถานที่เป็นพื้นที่ส่วนกลางทั้งหมด (ประตู ถนน ลานจอด กองกายภาพฯ ฯลฯ) — ไม่มีรายการของ MLC / LA / PMH

1. ทำสำเนา Sheet จริง (File → Make a copy) เก็บเป็นสำรอง แล้วสร้าง Sheet ทดสอบใหม่อีกไฟล์
2. ตั้ง Script Properties: `CCTV_V2_SHEET_ID` (ไฟล์ทดสอบ), `LEGACY_SHEET_ID` (ไฟล์เดิม) → รัน `setup()`
3. รัน `migrateLegacyDryRun()` — **อ่านอย่างเดียว** ตรวจว่าหัวตารางเดิมยังตรง 44 คอลัมน์ และดูว่าแต่ละแถวจะไปแท็บใด
4. เมื่อผลถูกต้อง ตั้ง `ALLOW_MIGRATION = yes` แล้วรัน `migrateLegacyCopy()` — **คัดลอก** เข้า `REQ_CENTRAL` พร้อมเลขแถวเดิมใน `legacyRow`
   (รันซ้ำไม่ซ้ำแถว, ไม่ลบและไม่แก้ Sheet เดิม) แล้วลบ `ALLOW_MIGRATION`
5. ตรวจนับ: จำนวนแถวใน Sheet เดิม = จำนวนแถวใน `REQ_CENTRAL` (Log แสดงทั้งสองค่า) และ `ALL_REQUESTS` แสดงครบ
6. ข้อมูลเดิม**ไม่ถูกจัดเข้า MLC/LA/PMH โดยอัตโนมัติ** — ถ้าชื่อสถานที่ใกล้เคียง ระบบแค่แจ้งเตือนให้เจ้าหน้าที่ยืนยันเอง

## ข้อสังเกตด้านความปลอดภัยของระบบเดิม (รายงานเท่านั้น ไม่ได้แก้)

1. `admin.html` ตรวจรหัสผ่านในเบราว์เซอร์ และมีรหัสผ่านอยู่ในไฟล์สาธารณะ (บรรทัด 404, 469, 481) — ควรเปลี่ยนรหัสและย้ายการตรวจไปฝั่งเซิร์ฟเวอร์
2. หน้าผู้ดูแลเรียก `?action=getData` และ `?action=updateRecord` โดยไม่มีการยืนยันตัวตนที่เซิร์ฟเวอร์ — ผู้ที่รู้ URL อาจอ่าน/แก้คำขอ (มีเลขบัตรประชาชน เบอร์โทร) ได้
3. Sheet จริงตั้งค่า “ทุกคนที่มีลิงก์ดูได้” และถูกอ่านเป็น CSV โดยระบบ PDF รายเดือน
4. รายชื่อ/อีเมลเจ้าหน้าที่ฝังอยู่ในหน้าแบบฟอร์มสาธารณะ

รุ่น v2 แก้ข้อ 1–2 ในส่วนของตัวเอง: ไม่มี `getData` แบบสาธารณะ, รหัสผู้ดูแลเก็บเป็น hash ใน Script Properties, API สาธารณะส่งเฉพาะยอดรวม

## ยังไม่ได้ทำ / รอข้อมูล

- หน้าผู้ดูแลรุ่นแยกหน่วยงาน (ปุ่มผู้ดูแลถูกถอดออกจาก `v2/index.html`) และแบบฟอร์มภาษาอังกฤษรุ่น v2
- การอัปโหลดไฟล์แนบของรุ่น v2 (ต้องกำหนดโฟลเดอร์ Drive ต่อหน่วยงานก่อน)
- รายชื่อและอีเมลเจ้าหน้าที่ของ MLC / LA / PMH และช่องทางแจ้งเตือน (อีเมล / LINE)
- ยังไม่ได้ทดสอบ: การรัน `Code.gs` ใน Apps Script จริง, การแสดง QR (ต้องโหลดไลบรารีจากอินเทอร์เน็ต)
